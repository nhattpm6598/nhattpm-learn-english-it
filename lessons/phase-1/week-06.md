# Tuần 6 — Ôn phát âm · Động từ khuyết thiếu · So sánh

> Checklist tuần: [phase-1-foundation.md](../../phase-1-foundation.md#tuần-6--động-từ-khuyết-thiếu-so-sánh)
> IPA: giọng Mỹ, ký hiệu theo Cambridge Dictionary (US).

## 1. Mục tiêu tuần

- Ôn lại 4 mảng phát âm đã học (âm cuối, /θ/ /ð/, trọng âm, ngữ điệu) qua chính các từ ngữ pháp của tuần — đặc biệt phân biệt **can** và **can't**.
- Dùng đúng **can / could / be able to**, **must / have to / should**, **may / might**.
- So sánh hơn, so sánh nhất, **as ... as** — đủ để so sánh hai công nghệ trong phỏng vấn.

---

## 2. Phát âm (tuần ôn tập)

### 2.1. Ôn âm cuối + can vs can't (Thứ 2)

Đây là cặp gây hiểu lầm nhiều nhất trong công việc ("I can finish it today" vs "I can't..."). Người Mỹ thường **không bật rõ /t/** trong can't, nên họ phân biệt bằng **nguyên âm và trọng âm**:

| | Phát âm | Nhấn? | Ví dụ |
| --- | --- | --- | --- |
| can (khẳng định) | /kən/ — rất ngắn, âm "cơn" | **Không** nhấn, nhấn động từ sau | I can **HELP**. /aɪ kən ˈhelp/ |
| can't | /kænt/ — âm /æ/ mở rộng, dài | **Có** nhấn | I **CAN'T** help. /aɪ ˈkænt help/ |
| can (đứng cuối, trả lời ngắn) | /kæn/ | Có nhấn | Yes, I **CAN**. |

Ôn âm cuối: **could** /kʊd/ (l câm, giữ /d/), **must** /mʌst/ (đủ /st/), **should** /ʃʊd/, **might** /maɪt/, **might not** /maɪt nɑːt/.

Luyện cặp:
| Câu | IPA rút gọn |
| --- | --- |
| I can come. | /aɪ kən ˈkʌm/ |
| I can't come. | /aɪ ˈkænt kʌm/ |
| She can code. | /ʃi kən ˈkoʊd/ |
| She can't code. | /ʃi ˈkænt koʊd/ |
| We can fix it. | /wi kən ˈfɪks‿ɪt/ |
| We can't fix it. | /wi ˈkænt fɪks‿ɪt/ |

### 2.2. Ôn /θ/ /ð/ qua so sánh (Thứ 3)

Phần so sánh dùng **than** /ðən/ (dạng yếu) và **the** /ðə/ liên tục — cơ hội luyện /ð/ hàng trăm lần:
- Java is faster **than** Python. /ðən/
- It's **the** best framework. /ðə/
- **This** is better **than that**. /ðɪs/ /ðən/ /ðæt/
- **Three** **thousand** **threads**. /θriː ˈθaʊ.zənd θredz/
- I **think** **they**'re both good. /θɪŋk ðer/

### 2.3. Ôn trọng âm (Thứ 4)

Từ trong bài so sánh hay bị nhấn sai:

| Từ | IPA | Nhấn |
| --- | --- | --- |
| comparison | /kəmˈper.ə.sən/ | com**PAR**ison |
| compare | /kəmˈper/ | com**PARE** |
| popular | /ˈpɑː.pjə.lɚ/ | **POP**ular |
| powerful | /ˈpaʊ.ɚ.fəl/ | **POW**erful |
| flexible | /ˈflek.sə.bəl/ | **FLEX**ible |
| efficient | /ɪˈfɪʃ.ənt/ | ef**FI**cient |
| expensive | /ɪkˈspen.sɪv/ | ex**PEN**sive |
| difficult | /ˈdɪf.ə.kəlt/ | **DIF**ficult |
| ecosystem | /ˈiː.koʊˌsɪs.təm/ | **E**cosystem |
| concurrency | /kənˈkɝː.ən.si/ | con**CUR**rency |
| verbose | /vɚˈboʊs/ | ver**BOSE** |
| mature | /məˈtʊr/ | ma**TURE** |

### 2.4. Ôn ngữ điệu (Thứ 5)

- So sánh hai thứ: lên ở vế 1, xuống ở vế 2: **Java** is **faster** ↗, but **Python** is **easier** ↘.
- Nhấn mạnh từ tương phản: Go is **SIMPLER** than Java, but Java has a **BIGGER** ecosystem.
- Câu hỏi lựa chọn: Which is **better** ↘, **Java** ↗ or **Kotlin** ↘?
- Khuyên nhủ (should) xuống giọng nhẹ nhàng: You **should** write more **tests** ↘.

### 2.5. Shadowing 1 phút (Thứ 6)

Lặp lại quy trình 5 bước của tuần 5 với **một đoạn audio mới**. Lần này chú ý thêm: tìm trong transcript các câu có **can / can't / should / must / -er than** và nghe xem người nói nhấn thế nào.

### 2.6. Câu luyện tập

1. I **can** read English, but I **can't** speak it well yet.
2. You **should** check the logs; the error **might** be in the config.
3. Kotlin is **more concise than** Java.
4. This is **the fastest** server we have.
5. Python is **not as fast as** Go, but it's **easier** to learn.

**Tongue twister:** *Can you can a can as a canner can can a can?* (luyện /kən/ vs /kæn/)

## 3. Ngữ pháp

### 3.1. can / could / be able to (Thứ 2)

| | Hiện tại | Quá khứ | Tương lai / thì khác |
| --- | --- | --- | --- |
| Khả năng | can / can't | could / couldn't | will be able to, have been able to |
| Xin phép, đề nghị | Can I...? / Could you...? (lịch sự hơn) | | |

Sau can/could: **V nguyên mẫu**, không thêm to, không chia: She can **speak** (không phải ~~can speaks~~, ~~can to speak~~).

**Cách dùng**
- **can**: khả năng hiện tại, xin phép thân mật. I **can** write SQL queries.
- **could**: khả năng chung trong quá khứ; yêu cầu lịch sự. I **could** read code when I was 15. / **Could** you repeat that, please?
- **be able to**: dùng khi can không chia được (sau will, have, to...) hoặc một lần làm được việc khó trong quá khứ. I **will be able to** start next month. / We **were able to** fix the bug before the release.

**Ví dụ**
- I **can** explain the architecture in English.
- **Can** I ask a question?
- **Could** you speak more slowly, please? (câu sống còn trong phỏng vấn!)
- I **couldn't** connect to the VPN this morning.
- After this course, I'**ll be able to** talk with my clients.

**Lỗi thường gặp:** ~~I can to speak~~, ~~She cans~~, ~~I will can~~ → I **will be able to**.

**Bài tập 1**
1. ___ you help me with this merge conflict? (lịch sự)
2. I ___ (not) log in yesterday. The server was down.
3. I hope I ___ speak English fluently next year.
4. She ___ write Java, Python and Go.
5. Sửa lỗi: "He can speaks three languages."
6. Sửa lỗi: "I will can finish it tomorrow."

### 3.2. must / have to / should (Thứ 3)

| Từ | Nghĩa | Ví dụ |
| --- | --- | --- |
| must | phải (người nói thấy cần thiết, quy định mạnh) | You **must** not share your password. |
| have to / has to | phải (do hoàn cảnh, quy định bên ngoài) | I **have to** wear a badge at the office. |
| don't have to | **không cần** phải | You **don't have to** come to the office on Fridays. |
| must not (mustn't) | **cấm** | You **mustn't** push directly to main. |
| should / shouldn't | nên / không nên (lời khuyên) | You **should** add more tests. |

Quá khứ của must/have to: **had to**. I **had to** work late yesterday.

**Phân biệt quan trọng:** **mustn't** (cấm) ≠ **don't have to** (không bắt buộc).
- You **mustn't** deploy on Friday. = Cấm deploy thứ Sáu.
- You **don't have to** deploy on Friday. = Không cần deploy thứ Sáu (muốn thì cứ làm).

**Ví dụ**
- All code **must** be reviewed before merging.
- I **have to** finish this report by 5 p.m.
- She **has to** join an on-call rotation.
- You **should** use environment variables for secrets.
- We **had to** roll back the release last night.

**Bài tập 2**
1. Passwords ___ be at least 12 characters. (quy định)
2. You ___ bring your laptop; we have one for you. (không cần)
3. You ___ commit API keys to Git. (cấm)
4. I think you ___ ask the team lead. (lời khuyên)
5. Yesterday I ___ (have to) restart the server three times.
6. ___ she ___ work on weekends? (câu hỏi với have to)

### 3.3. may / might (Thứ 4)

**Công thức:** S + may/might + V nguyên mẫu · Phủ định: may not / might not (không viết tắt mayn't)

**Cách dùng:** khả năng **không chắc chắn** (khoảng 30–50%). Trong giao tiếp hằng ngày, **might** phổ biến hơn. **May** còn dùng để xin phép trang trọng: **May** I come in?

**Ví dụ**
- The bug **might** be in the cache layer.
- I **may** be a few minutes late.
- We **might not** finish this feature in this sprint.
- It **might** be a network problem. Let me check.
- **May** I ask a question about the role?

**Mức độ chắc chắn:** will (100%) > should / probably will (80%) > may / might (40%) > might not > won't (0%).

**Lỗi thường gặp:** ~~Maybe it is will rain.~~ → It **might** rain. / **Maybe** it will rain. (maybe là trạng từ, đứng đầu câu; may be là động từ: It may be true.)

**Bài tập 3**
1. I'm not sure. The server ___ be down.
2. I ___ not come to the party. I have a deadline.
3. ___ I use your charger? (xin phép trang trọng)
4. Sửa lỗi: "May be the API is slow."
5. Viết lại với might: "Perhaps we will use Kafka."

### 3.4. So sánh hơn, so sánh nhất (Thứ 5)

| Loại tính từ | So sánh hơn | So sánh nhất |
| --- | --- | --- |
| 1 âm tiết | fast → fast**er** than | the fast**est** |
| Tận cùng -e | safe → safe**r** | the safe**st** |
| 1 nguyên âm + 1 phụ âm | big → big**ger** | the big**gest** |
| 2 âm tiết tận cùng -y | easy → eas**ier** | the eas**iest** |
| 2+ âm tiết (còn lại) | **more** popular than | **the most** popular |
| Bất quy tắc | good → **better**, bad → **worse**, far → **further** | **the best**, **the worst**, **the furthest** |

Kém hơn: **less** + tính từ dài: Python is **less verbose** than Java.

**Ví dụ**
- Go is **faster than** Python.
- Kotlin is **more concise than** Java.
- Java has **a bigger** ecosystem **than** Go.
- PostgreSQL is **one of the most popular** databases.
- This was **the worst** incident **in** our company's history.
- The new version is **much better** than the old one. (nhấn mạnh: much, a lot, a bit)

**Lỗi thường gặp:** ~~more faster~~, ~~more better~~ (thừa more); ~~more easy~~ → easier; quên **than** hoặc dùng ~~then~~; quên **the** trước so sánh nhất.

**Bài tập 4**
1. Rust is ___ (safe) than C.
2. This query is ___ (slow) than the old one.
3. Python is ___ (easy) to learn than C++.
4. JavaScript is one of ___ (popular) languages in the world.
5. This is ___ (bad) bug I've ever seen.
6. Microservices are ___ (complex) than a monolith.
7. Sửa lỗi: "Go is more faster then Java."

### 3.5. as ... as (Thứ 6)

**Công thức**
- Bằng: **as** + tính từ/trạng từ + **as**: Kotlin is **as fast as** Java.
- Không bằng: **not as** + tính từ + **as**: Python is **not as fast as** Go.
- Gấp: **twice as** fast **as**, **three times as** big **as**.
- Giống: **the same as**, **similar to**, **different from**.

**Ví dụ**
- The new API is **as reliable as** the old one.
- Our app is**n't as popular as** our competitor's.
- The new server is **twice as fast as** the old one.
- My English is **not as good as** my Vietnamese, but it's improving.
- Kotlin's syntax is **similar to** Swift, but **different from** Java.

**Bài tập 5**
1. My laptop is ___ (fast) yours. (bằng nhau)
2. MySQL is not ___ (flexible) PostgreSQL.
3. The new build is ___ (twice / fast) the old one.
4. Kotlin is similar ___ Java.
5. Viết lại với "not as ... as": "Java is more verbose than Kotlin." → "Kotlin ___."

## 6. Bài nói / ghi âm Thứ 7 — So sánh Java với một ngôn ngữ khác (5+ câu)

**Yêu cầu:** dùng ít nhất 3 cấu trúc so sánh và 2 modal. Chú ý can /kən/ vs can't /kænt/, than /ðən/.

**Bài mẫu (Java vs Python):**

> I'd like to compare Java and Python. Python is easier to learn than Java, and its syntax is much more concise. However, Java is usually faster, and in my opinion, it's more reliable for large enterprise systems. Python isn't as good as Java for multi-threaded applications, but it's the best choice for data science and machine learning. If you're a beginner, you should start with Python. But if you want to build big backend systems, Java might be a better option.

**Bản dịch:**

> Tôi muốn so sánh Java và Python. Python dễ học hơn Java và cú pháp ngắn gọn hơn nhiều. Tuy nhiên Java thường nhanh hơn, và theo tôi, nó đáng tin cậy hơn cho các hệ thống doanh nghiệp lớn. Python không tốt bằng Java cho ứng dụng đa luồng, nhưng nó là lựa chọn tốt nhất cho khoa học dữ liệu và học máy. Nếu bạn là người mới, bạn nên bắt đầu với Python. Nhưng nếu muốn xây dựng hệ thống backend lớn thì Java có thể là lựa chọn tốt hơn.

**Phương án khác để tự viết:** Java vs Kotlin (concise, null safety, Android), Java vs Go (simple, concurrency, fast startup, smaller binary), Java vs C# (very similar, .NET ecosystem).

## 7. Đáp án

**Bài tập 1:** 1. Could · 2. couldn't · 3. will be able to (hoặc can) · 4. can · 5. He can **speak** three languages. · 6. I **will be able to** finish it tomorrow. (hoặc I can finish it tomorrow.)

**Bài tập 2:** 1. must · 2. don't have to · 3. mustn't · 4. should · 5. had to · 6. Does she have to work

**Bài tập 3:** 1. might (may) · 2. might (may) · 3. May · 4. **Maybe** the API is slow. (hoặc The API may be slow.) · 5. We might use Kafka.

**Bài tập 4:** 1. safer · 2. slower · 3. easier · 4. the most popular · 5. the worst · 6. more complex · 7. Go is **faster than** Java.

**Bài tập 5:** 1. as fast as · 2. as flexible as · 3. twice as fast as · 4. to · 5. Kotlin **isn't as verbose as** Java.
