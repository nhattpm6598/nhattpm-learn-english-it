# Tuần 25 — Email và viết (commit, PR, CV, LinkedIn)

> Giai đoạn 3 · Tuần 8/9 · Checklist gốc: [phase-3-it-english.md](../../phase-3-it-english.md#tuần-25--email-và-viết)

## 1. Mục tiêu tuần

- Viết email công việc ngắn, rõ, lịch sự: xin nghỉ, báo trễ deadline, hỏi làm rõ yêu cầu, follow-up.
- Viết lại 3 mô tả PR gần nhất bằng tiếng Anh theo mẫu *What / Why / How / Testing*.
- Viết commit message theo chuẩn **Conventional Commits**.
- Viết **3–5 bullet CV mỗi dự án** theo công thức *Action verb + What + How + Result (số liệu)*.
- Viết **LinkedIn summary** (About) 120–200 từ.

**4 nguyên tắc viết tiếng Anh trong công việc**
1. **Ngắn trước, chi tiết sau.** Câu đầu tiên nói mục đích. Người đọc chỉ đọc 2 dòng đầu.
2. **Một email, một việc.** Muốn hỏi 3 việc, đánh số 1-2-3.
3. **Câu chủ động, động từ mạnh:** "I fixed the bug" tốt hơn "The bug was fixed by me".
4. **Kiểm tra lại** bằng Grammarly hoặc AI, nhưng đọc to trước khi gửi.

**Lỗi người Việt hay mắc khi viết:**
- Thiếu mạo từ: ~~I fixed bug in login page~~ → I fixed **a** bug on **the** login page.
- Thiếu -s: ~~The service handle 1,000 request~~ → The service handle**s** 1,000 request**s**.
- Dịch từng chữ: ~~Please help me check this~~ → Could you take a look at this?
- Lạm dụng "kindly", "do the needful", "revert" (nghĩa là "trả lời" chỉ dùng ở Ấn Độ; nên dùng "reply/get back to me").

## 3. Mẫu câu công việc

**Mở email**
1. Hi Mark, (đủ lịch sự cho đồng nghiệp; "Dear Mr. Smith" chỉ khi rất trang trọng)
2. I hope you're doing well. (chỉ khi lâu không liên lạc, không bắt buộc)
3. I'm writing to ask about ...
4. Quick question about ...
5. Following our call yesterday, ...

**Yêu cầu / hỏi**
6. Could you please ...?
7. Would it be possible to ...?
8. I'd appreciate it if you could ...
9. Could you clarify what should happen when ...?
10. Just to confirm, ...?

**Báo tin xấu / trễ**
11. Unfortunately, ...
12. I wanted to let you know that ...
13. I underestimated the effort needed for ...
14. The new estimate is ...
15. To reduce the impact, I suggest ...
16. Sorry for the inconvenience.

**Gửi kèm / thông tin**
17. Please find the report attached. / I've attached the report.
18. Here's the link to the PR: ...
19. For context, ...
20. As mentioned in my previous email, ...

**Follow-up**
21. Just following up on this.
22. Any update on ...?
23. Gentle reminder: ...

**Kết thúc**
24. Let me know if you have any questions.
25. Happy to discuss on a call if that's easier.
26. Thanks in advance.
27. Best regards, / Best, / Thanks,

## 4. Hội thoại / tình huống mẫu

### Tình huống 1: Tin nhắn Slack hỏi làm rõ yêu cầu (qua lại)

> **Nhat:** Hi Laura, quick question about PROD-512 (CSV export). Should the export include cancelled orders? The ticket doesn't say.
> **Laura:** Good question! No, only completed and shipped orders.
> **Nhat:** Got it, thanks. One more: should the dates be in the user's timezone or UTC?
> **Laura:** User's timezone, please. Accountants will open it in Excel.
> **Nhat:** Perfect. I'll update the acceptance criteria in the ticket so QA knows too.

### Tình huống 2: Gọi điện báo trễ deadline với manager

> **Nhat:** Hi Kate, do you have five minutes? I wanted to give you a heads-up about the reporting feature.
> **Kate:** Sure, what's up?
> **Nhat:** It won't be ready on Friday. The data from the old system has a lot of duplicates, and cleaning it is taking longer than I estimated.
> **Kate:** How much longer?
> **Nhat:** About three more days, so next Wednesday. But I have an option: I can release the report on Friday with data from the last six months, which is clean, and add the older data next week.
> **Kate:** That works. The client mainly cares about recent data anyway.
> **Nhat:** Great. I'll send a short email with the new plan so everyone's aligned.

## 5. Bài mẫu: nói về PR và về bản thân

### 5.1 Giải thích PR của bạn cho reviewer (nói, 1 phút)

> This PR adds rate limiting to the public API. Right now, one client can send thousands of requests per second and slow down everyone else. I added a filter in the API gateway using a token bucket stored in Redis, so it works across all instances. The limit is a hundred requests per minute per API key, and it's configurable. When a client goes over the limit, we return a 429 with a `Retry-After` header. I added unit tests for the bucket logic and an integration test with Testcontainers. The part I'd like you to look at most carefully is the Lua script, because it has to be atomic.

**5 cụm từ dùng lại:** *This PR adds ... · Right now, ... · I added ... so it works ... · When ..., we return ... · The part I'd like you to look at most carefully is ...*

### 5.2 "Tell me about yourself" phiên bản 60 giây (dựa trên LinkedIn summary)

I've worked on e-commerce and payment systems, where I designed REST APIs, worked with PostgreSQL, Redis and Kafka, and ran services on Kubernetes. I also do frontend work with React, so I'm comfortable building a feature end to end. Recently I've been focusing on system design and mentoring two junior developers. Now I'm looking for a senior role in an international team where I can take more ownership of architecture.

### 6.2 Commit message (Conventional Commits)

Cấu trúc: `<type>(<scope>): <summary in imperative mood>`
Kiểu thường dùng: `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `perf`, `ci`.
Summary dùng **động từ nguyên mẫu** (imperative): *add*, không phải *added/adds*; ≤ 50–72 ký tự; không chấm cuối.

```
feat(order): add CSV export for order history
fix(auth): handle expired refresh tokens correctly
refactor(payment): extract fee calculation into FeeCalculator
perf(catalog): cache product details in Redis
test(order): add tests for empty cart checkout
docs: update local setup instructions
```

Commit có thân bài (body) giải thích **why**:
```
fix(checkout): prevent NPE when discount has no end date

Discounts created before v4.0 have a null `endDate`. DiscountCalculator assumed
it was always set, which caused 500 errors at checkout.

Treat a null end date as "no expiry" and add a regression test.

Fixes PROD-530
```

### 6.3 Mô tả PR

```
## Summary
Add rate limiting to the public API (100 requests/min per API key).

## Why
One client sent ~3,000 req/s last week and increased p99 latency for everyone
(see incident INC-77).

## Changes
- New `RateLimitFilter` in the gateway using a token bucket in Redis.
- Limit is configurable via `ratelimit.requests-per-minute`.
- Returns 429 with a `Retry-After` header.

## How to test
1. Run `docker compose up` and start the gateway.
2. Send 101 requests in one minute with the same API key.
3. The 101st request should return 429.

## Notes for reviewers
The Lua script in `token_bucket.lua` must be atomic; please check it carefully.
```

## 7. Bài tập

1. **Sửa lỗi:** (a) "Please help me check this PR." (b) "I will send you the report in EOD." (c) "Kindly revert me ASAP." (d) "I fixed bug in payment service, it make the API slow."
2. **Viết commit message** cho: (a) thêm endpoint lấy danh sách hóa đơn (b) sửa lỗi timezone khi xuất báo cáo (c) đổi tên class `Util` thành `DateUtils`.
3. **Viết lại bullet CV:** (a) "Responsible for writing APIs." (b) "Worked on database optimization." (c) "Participated in Kubernetes migration."
4. **Viết email** xin gia hạn 2 ngày cho một task vì bạn phát hiện thêm edge case. ≤ 120 từ.
5. **T3:** viết lại 3 mô tả PR gần nhất của bạn theo mẫu 6.3.
6. **T4:** viết 3–5 bullet CV cho mỗi dự án lớn (ít nhất 2 dự án).
7. **T6:** viết LinkedIn summary 120–200 từ. Kiểm tra bằng Grammarly, rồi đọc to.
8. **Nói:** dùng mẫu 5.2, nói "Tell me about yourself" 60–90 giây với thông tin thật của bạn.

## 8. Tài liệu

- [Conventional Commits](https://www.conventionalcommits.org) — quy chuẩn commit message.
- [Grammarly](https://www.grammarly.com) — kiểm tra ngữ pháp, giọng văn; bật tiện ích trình duyệt khi viết Slack/Jira/LinkedIn.
- [Google Engineering Practices](https://google.github.io/eng-practices/review/) — có phần "Writing good CL descriptions" (CL = PR).
- [roadmap.sh](https://roadmap.sh) — dùng để liệt kê kỹ năng đúng tên gọi trong CV.
- [Cambridge Dictionary](https://dictionary.cambridge.org) — kiểm tra cách dùng từ, collocation.
- Prompt AI sửa CV:
  ```
  You are a tech recruiter in Europe. Review my CV bullet points for a Senior Java
  Backend role. For each bullet: point out grammar mistakes, make it stronger with an
  action verb and a measurable result, and do not invent numbers.
  ```
